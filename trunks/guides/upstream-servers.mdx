An upstream server is an MCP server you register in Trunks. In enterprise mode, only administrators can register, change or remove one.

Registration is all-or-nothing. Trunks connects to the server, completes the MCP handshake and lists its tools. If any step fails, Trunks stores nothing and the command prints the reason.

## Local process (stdio)

Trunks starts the server as a process and talks to it over stdin and stdout.

```bash
trunks register --name files \
  --command npx --arg -y --arg @modelcontextprotocol/server-filesystem --arg /srv/shared \
  --env LOG_LEVEL=warn \
  --session-mode stateful
```

- Repeat `--arg` once per argument, in order. Repeat `--env NAME=value` once per variable.
- The process runs on the machine (or in the container) where Trunks runs, as the Trunks user. It gets the Trunks environment plus the variables you pass with `--env`.
- When the session ends, Trunks terminates the process and everything it started.
- What the process writes to stderr appears in the Trunks log. Trunks replaces the values you passed with `--env` by `[redacted]`. See [Operations](/trunks/guides/operations).

<Warning>
  A stdio server runs its command on the Trunks host. Only register commands you trust. The container image without the `-stdio` suffix has no `npx` or `uvx`; use `ghcr.io/websublime/trunks:v0.1.0-rc.2-stdio` for stdio servers that need them.
</Warning>

## Remote server (Streamable HTTP)

Pass `--url` and Trunks uses the `streamable_http` transport.

```bash
trunks register --name github \
  --url https://api.githubcopilot.com/mcp/ \
  --bearer-token "$GITHUB_TOKEN"
```

- Trunks sends `--bearer-token` as `Authorization: Bearer …`.
- `--header` adds any other header. Write it as `Name: value` or `Name=value`, and repeat it per header. Trunks splits on the first `:` or `=`.
- An explicit `Authorization` header takes precedence over `--bearer-token`.
- A server on the Trunks host itself is `http://127.0.0.1:<port>/…`. When Trunks runs in a container, the host is usually `http://host.docker.internal:<port>/…`.

<Note>
  You can't register servers that only speak the older HTTP+SSE transport.
</Note>

## Remote server with OAuth

If the server answers the first connection with an OAuth challenge, the CLI runs the authorization in your browser.

```bash
trunks register --name jira --url https://mcp.example.com/mcp
```

<Steps>
  <Step title="Open the authorization URL">
    The CLI prints an authorization URL and tries to open it in your browser.
  </Step>
  <Step title="Approve access">
    Sign in at the provider and approve access.
  </Step>
  <Step title="Finish the registration">
    The provider sends the browser back to a temporary listener the CLI opened on `127.0.0.1`, and the registration finishes.
  </Step>
</Steps>

Trunks registers itself with the authorization server when the server supports dynamic client registration. Otherwise, create an OAuth client at the provider and pass it:

```bash
trunks register --name jira --url https://mcp.example.com/mcp \
  --oauth-client-id "$CLIENT_ID" --oauth-client-secret "$CLIENT_SECRET" \
  --oauth-scope read --oauth-scope write
```

### Redirect to another machine

If the redirect can't reach the machine running the CLI, pass the redirect URI registered for your OAuth client with `--oauth-redirect-uri`. The CLI then prints the authorization URL and a session id, and stops. After you approve, take `code` and `state` from the redirect and run:

```bash
trunks oauth-complete <session-id> --code <code> --state <state>
```

<Note>
  An authorization that isn't completed within 10 minutes expires. Run `trunks register` again. Trunks stores the tokens and refreshes them when they expire.
</Note>

## Session modes

`--session-mode` (or `session_mode` in a file) sets how Trunks holds the connection to the upstream:

| Mode | Behaviour |
|---|---|
| `stateless` | The default. Trunks opens a fresh connection for each call and closes it afterwards. For a stdio server, that means a new process per call. |
| `stateful` | Trunks keeps one connection per server and reuses it for every call. A transport error or a timeout closes the connection, and the next call reopens it. |

Use `stateful` for servers that are slow to start or that keep state between calls. By default a stateful connection stays open until Trunks stops; set `TRUNKS_SESSION_IDLE_TIMEOUT_SEC` to close connections idle for that many seconds. See [Configuration](/trunks/reference/configuration).

## In the web console

You can do everything above from the console's **Servers** page. In enterprise mode, only administrators can.

- **Register server** opens a form with the same fields as the flags: a local process (command, arguments, environment variables) or a remote server (URL, bearer token, headers), and the session mode. Trunks receives values of variables, headers and tokens once and never shows them again.
- When a remote server asks for OAuth, the console shows **Authorization required**. **Open provider** opens the provider in a new window. Once you approve, the provider sends the browser back to Trunks and the server is registered. As with the CLI, Trunks stores nothing until then, and the request expires after 10 minutes.
- For a provider without dynamic client registration, open **Authorization with your own OAuth client** in the form. It shows the redirect URI to register at the provider, `<public URL>/api/dashboard/oauth/callback`, and takes the client ID, secret and scopes.
- A server's page has a switch for the whole server, one for each tool, prompt and resource, and **Delete**.

Replacing a registered server's definition (`--force`), export and import are CLI only.

## From a file

Write the same definition as JSON, for version control or automation:

```json github.json
{
  "name": "github",
  "transport": "streamable_http",
  "description": "GitHub tools",
  "url": "https://api.githubcopilot.com/mcp/",
  "bearer_token": "${GITHUB_TOKEN}",
  "session_mode": "stateless"
}
```

```bash
trunks register -c github.json
```

The CLI replaces every `$\{VAR\}` in a string value with that environment variable of the CLI process. A variable that isn't set is an error, so credentials never end up empty. Only the `$\{NAME\}` form is recognized. Flags you pass alongside `-c` override the file.

| Field | For | Meaning |
|---|---|---|
| `name` | all | Required. Server name: letters, digits, `_`, `-`. |
| `transport` | all | Required. `stdio` or `streamable_http`. |
| `description` | all | Free text. |
| `session_mode` | all | `stateless` (default) or `stateful`. |
| `command`, `args`, `env` | `stdio` | Program, argument list, environment variables (object). |
| `url` | `streamable_http` | Server URL. |
| `bearer_token`, `headers` | `streamable_http` | Credentials and extra headers (object). |
| `oauth_redirect_uri`, `oauth_client_id`, `oauth_client_secret`, `oauth_scopes` | `streamable_http` | OAuth, as the flags above. `oauth_scopes` is a list. |

<Tip>
  With flags and no file, you can leave out `--transport`. Trunks uses `streamable_http` when you pass `--url`, and `stdio` otherwise.
</Tip>

## Enable, disable and remove

| To | Run |
|---|---|
| Replace a server's definition, or re-read its tools | `trunks register … --force` |
| Hide a server without removing it | `trunks disable server <name>` / `trunks enable server <name>` |
| Hide one tool, prompt or resource | `trunks disable tool <server>__<tool>` (also `prompt <server>__<prompt>`, `resource <trunks:// URI>`) |
| Hide all tools of a server | `trunks disable tool <server>` (also `prompt`, `resource`) |
| Remove a server | `trunks deregister <name>` |

Disabling a server also hides its tools, prompts and resources; the command lists what it affected. Removing a server also removes its stored OAuth tokens. Grants and tool groups refer to servers by name, so they apply again if you later register a server with the same name.

See [`trunks register`](/trunks/reference/cli#trunks-register), [`trunks enable`](/trunks/reference/cli#trunks-enable), [`trunks disable`](/trunks/reference/cli#trunks-disable) and [`trunks deregister`](/trunks/reference/cli#trunks-deregister).

## Inspect

```bash
trunks list servers
trunks list tools --server github
trunks list prompts
trunks list resources
trunks usage github__create_issue                 # input schema of a tool
trunks get prompt docs__summarize --arg topic=mcp # render a prompt
trunks get resource '<trunks:// URI>' --read      # read a resource
```

## Export

```bash
trunks export -d backup/
```

This writes `backup/servers/<name>.json` and `backup/groups/<name>.json`, in the format that `trunks register -c` and `trunks create group -c` accept. Without `-d`, the directory is `.trunks`. The directory must not exist or must be empty.

<Warning>
  The files contain the credentials in clear text: bearer tokens, headers and `env` values.
</Warning>

The export leaves out:

- OAuth client registrations and tokens. You have to authorize a server registered with OAuth again where you import it.
- Which entries are disabled.
- Users, teams, grants and MCP clients.

For a full copy, back up the database. See [Operations](/trunks/guides/operations).

## Limits

- The MCP handshake with an upstream must finish within `TRUNKS_UPSTREAM_INIT_TIMEOUT_SEC` (default 30 seconds).
- Each call to an upstream must be answered within `TRUNKS_REQUEST_TIMEOUT_SEC` (default 300 seconds; `0` disables it). After that, the caller gets an error that names the upstream, and a `stateful` connection is reopened on the next call.
- Trunks doesn't retry a failed call.

See [Configuration](/trunks/reference/configuration) for both settings.
