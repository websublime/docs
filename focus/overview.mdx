<h2 id="overview">Overview</h2>

Focus is a Rust engine for AI-DLC (AI-Driven Development Life Cycle). AI-DLC organizes your work with a coding assistant into stages grouped by phase and selected by a scope, with human approval gates and an audit trail. Focus targets Claude Code, Cursor and GitHub Copilot. It is for developers who run AI-DLC workflows and for contributors to the engine.

Focus is a fork of [`awslabs/aidlc-workflows`](https://github.com/awslabs/aidlc-workflows), frozen at upstream version 2.11.0, commit `2a555f7a4387cd1b8254029cccb9fd1e99974574`, and checked for parity against it.

<h2 id="what-you-can-do">What you can do</h2>

- Compile and query the stage graph with `focus engine graph`: dependency order, the stages of a scope, artifact producers and consumers, plan validation and export.
- Append to and read the audit ledger with `focus engine audit`, and compile the runtime graph of a workflow with `focus engine runtime`.
- Move a workflow through its stages and approval gates with `focus engine state`: `advance`, `skip`, `gate-start`, `approve`, `reject`, `park` and more.
- Jump to another stage with `focus engine jump resolve` and `focus engine jump execute`.
- Start a piece of work and inspect the project with `focus engine utility intent-create`, `detect`, `now` and `status`.
- Run harness hooks on a host payload with `focus engine hook <name>`, for example `session-start` or `session-end`.

<h2 id="install">Install</h2>

Focus has no release yet. Build it from source with Rust 1.89 or later:

```bash
git clone https://github.com/websublime/focus.git
cd focus
cargo build --release
```

The binary is `target/release/focus`. There is no harness installer yet: Focus does not create the `.claude/`, `.cursor/` or `focus/` trees in your project. {/* leak-lint: allow .claude/ is the harness directory Focus targets, not an agent file of this site */}

<h2 id="quick-example">Quick example</h2>

Compile the stage graph from the bundled upstream Markdown, outside any project:

```bash
focus engine graph compile --harness claude --core fixtures/upstream/core --out /tmp/compiled
```

Inside a project with a harness installed, list the stages a scope runs:

```bash
focus engine graph scope bugfix
```

<h2 id="status">Status</h2>

- **Works:** the stage graph, the audit ledger, the runtime graph, the workflow state file with its transitions, gates and jumps, creating a piece of work, settings files, and 12 harness hooks plus the `guard-tool-call` group.
- **Not yet:** the orchestrator. Checks that depend on it are refused by name.
- **Refused as not ported:** 30 `utility` verbs (for example `doctor`, `init`, `intent`, `space`), `jump reopen`, and 3 hooks: `continue-workflow`, `deliver-stage-rules` and `fold-usage`.
- **Not available:** published binaries, installers and a harness installer. Adapters for Cursor and GitHub Copilot do not exist yet, so in practice only Claude Code hooks work.
- `graph resolve` runs only when `FOCUS_GRAPH_RESOLVE=1` is set.

<h2 id="contribute">Contribute</h2>

<Steps>
  <Step title="Fork and branch">
    Fork `websublime/focus` and create a short-lived branch from `main`.
  </Step>
  <Step title="Run the checks">
    Run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace`.
  </Step>
  <Step title="Open a pull request">
    Open a pull request against `main`. It merges only when CI passes on Linux, macOS and Windows.
  </Step>
</Steps>

<Tip>`cargo test` replays the parity fixtures without Bun or an upstream checkout.</Tip>
